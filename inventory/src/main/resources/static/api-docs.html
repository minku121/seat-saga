SeatSaga Inventory API

A practical guide to the endpoints used by the SeatSaga inventory service.

Local base URL: http://localhost:8082 · Content type: application/json

Admin authentication

Get a JWT token before calling any /api/admin/ endpoint. Keep the admin secret private.

POST/api/admin/token

Send the configured admin secret:

{"secret":"<ADMIN_SECRET>"}

Alternatively, use the X-Admin-Key header or the supported ?secret= query parameter.

Use the returned token for admin requests:

Authorization: Bearer <JWT_TOKEN>

Public event APIs

GET/api/events

Lists active events and their available details. No token required.

GET/api/events/{id}

Returns a single event by its numeric ID.

GET/api/events/{eventId}/seat-types

Lists an event's seat tiers, prices, quantities and booking counts.

Admin event APIs

POST/api/admin/events

Creates an event. Requires a Bearer JWT.

{
  "name": "Summer Rock Fest",
  "description": "Live music",
  "venue": "Grand Arena",
  "maxCapacity": 1000,
  "eventDate": "2027-08-15T18:00:00",
  "status": "PUBLISHED"
}

Required fields: name, venue, maxCapacity and eventDate. Confirm optional fields and accepted status values against your backend.

PUT/api/admin/events/{id}

Updates an event's details and capacity. Requires a Bearer JWT.

DELETE/api/admin/events/{id}

Deletes or cancels an event, depending on the backend implementation.

Admin seat-type APIs

POST/api/admin/events/{eventId}/seat-types

Creates a seat tier for an event.

{
  "code": "VIP",
  "name": "VIP Reserved",
  "description": "Front row seats",
  "price": 199.99,
  "quantity": 30
}
POST/api/admin/events/{eventId}/seat-types/{code}/seats

Adds seats to an existing seat tier.

{"quantity": 20}
PATCH/api/admin/events/{eventId}/seat-types/{code}

Partially updates an existing seat tier.

{
  "name": "VIP Plus",
  "description": "Updated description",
  "price": 249.99,
  "active": true
}

Common HTTP responses

  • 200 — Request succeeded.
  • 201 — Resource created.
  • 204 — Successful response with no body.
  • 400 — Invalid request data.
  • 401 — Missing or invalid authentication.
  • 404 — Resource not found.
  • 409 — Resource conflict.
